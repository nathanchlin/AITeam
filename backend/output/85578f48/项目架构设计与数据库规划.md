# 项目架构设计与数据库规划报告

## 1. 系统架构设计

### 1.1 整体架构

基于球球大作战游戏的实时多人特性和高并发需求，设计采用微服务架构，分为以下几层：

```

│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐    │

### 1.2 微服务拆分

#### 1.2.1 游戏逻辑服务
- **职责**：处理游戏核心逻辑，包括玩家移动、吃球、分裂等
- **技术栈**：Node.js + Socket.io
- **特点**：无状态设计，支持水平扩展

#### 1.2.2 社交关系服务
- **职责**：处理好友系统、聊天、分享等功能
- **技术栈**：Node.js + Express
- **特点**：关系型数据为主，使用PostgreSQL存储

#### 1.2.3 排行榜服务
- **职责**：维护全球、好友、本地排行榜
- **技术栈**：Node.js + Redis
- **特点**：实时性要求高，使用Redis的有序集合

#### 1.2.4 玩家服务
- **职责**：处理玩家账户、个人信息、成就等
- **技术栈**：Node.js + Express
- **特点**：读写分离，主从数据库架构

#### 1.2.5 房间服务
- **职责**：管理游戏房间，匹配玩家
- **技术栈**：Node.js + Socket.io
- **特点**：会话状态管理，房间生命周期控制

#### 1.2.6 日志服务
- **职责**：收集游戏行为日志，分析玩家行为
- **技术栈**：Node.js + ELK Stack
- **特点**：高吞吐量，异步处理

### 1.3 通信架构

#### 1.3.1 客户端-服务器通信
- **协议**：WebSocket (Socket.io)
- **消息类型**：
  - 玩家位置更新
  - 球体状态变化
  - 碰撞检测
  - 聊天消息
  - 排行榜更新

#### 1.3.2 服务器内部通信
- **协议**：REST API + gRPC
- **认证**：JWT (JSON Web Token)
- **负载均衡**：基于玩家数量的动态负载均衡

## 2. 数据库设计

### 2.1 数据库选型与分工

| 数据库 | 用途 | 数据类型 | 特点 |
|--------|------|----------|------|
| MongoDB | 玩家数据、游戏数据 | 半结构化数据 | 灵活扩展，适合游戏状态存储 |
| Redis | 缓存、实时排行榜、会话管理 | 键值对、有序集合 | 高性能，内存操作 |
| PostgreSQL | 关系数据、社交关系 | 结构化数据 | 强一致性，支持复杂查询 |

### 2.4 PostgreSQL 数据库设计

#### 2.4.1 用户表 (users)
```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    last_login TIMESTAMP WITH TIME ZONE,
    is_active BOOLEAN DEFAULT TRUE
);
```

#### 2.4.2 好友关系表 (friendships)
```sql
CREATE TABLE friendships (
    id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(id),
    friend_id INTEGER REFERENCES users(id),
    status VARCHAR(20) DEFAULT 'pending', -- pending, accepted, blocked
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(user_id, friend_id)
);
```

#### 2.4.3 聊天消息表 (chat_messages)
```sql
CREATE TABLE chat_messages (
    id SERIAL PRIMARY KEY,
    room_id VARCHAR(50),
    sender_id INTEGER REFERENCES users(id),
    receiver_id INTEGER REFERENCES users(id),
    message TEXT,
    message_type VARCHAR(20) DEFAULT 'text', -- text, emoji, image
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    is_read BOOLEAN DEFAULT FALSE
);
```

#### 2.4.4 交易记录表 (transactions)
```sql
CREATE TABLE transactions (
    id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(id),
    type VARCHAR(20) NOT NULL, -- purchase, reward, refund
    amount INTEGER NOT NULL,
    currency VARCHAR(10) DEFAULT 'coins',
    description TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    reference_id VARCHAR(100) -- 订单ID或交易引用
);
```
